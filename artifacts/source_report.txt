Executive Summary & Business 
Objectives 
What the platform manages, why it exists, and where Power BI adds value.  
 
 
Executive Summary 
The Andalusia Academy Work Management System is an operational management platform that connects Academy 
Programs, lifecycle stages, Position-owned work, tasks, team workload, instructors, schedules, finances, documents, 
reports, approvals, and audit history. It is designed so operational work can be executed in the same environment in 
which management reviews readiness and controls Program progression.  
The system separates operational execution from management governance. Contributors complete the work owned 
by their Position; the Academy Manager reviews readiness, blockers, evidence, and handoffs, and retains authority 
to complete lifecycle stages and close Programs. Revision 20.2 adds server-side authentication and authorization for 
Admin and User accounts. 
Business Objectives 
• Centralize Academy operational information and reduce duplicate entry across workflow and personal tasks. 
• Provide end-to-end visibility from Program request through final closure. 
• Make lifecycle requirements, blockers, ownership, readiness, and next actions explicit. 
• Assign and monitor Position-owned tasks while keeping Program stage state distinct from personal task progress. 
• Monitor team capacity, instructor readiness, delivery schedules, Program finance, documents, and management 
approvals. 
• Provide auditable management decisions and handoffs. 
• Create a reliable operational source from which historical analytics and management reporting can be built. 
Where Power BI Adds Value 
The operational application is optimized for current work and decisions. Power BI should complement it with historical 
trends, cross-Program comparison, stage aging, SLA analysis, task aging, capacity trends, Instructor utilization, 
delivery performance, financial variance, drill-through, forecasting, and governed executive reporting.

Authentication & Session Security 
• Two first-run accounts are created automatically: admin (Academy Manager) and user (Program Coordinator). 
• Temporary passwords are generated on first server start and must be replaced at first sign-in. 
• Authentication uses an HttpOnly, SameSite=Lax session cookie with a 12-hour rolling timeout by default. 
• CSRF tokens protect authenticated state-changing API requests. 
• Login throttling is applied after repeated failures; logout invalidates the server session. 
• Manager-only API actions are enforced server-side; a contributor cannot advance Program lifecycle stages through the 
API.

3.21  Program Lifecycle / programStageFlow 
The current Program Stage Flow is a scoped lifecycle component introduced in Revision 20.1 and preserved in Revision 
20.2. It separates the actual current stage from the stage selected for inspection, displays completed-stage count and 
overall readiness, and switches to a vertical timeline on phone/tablet portrait layouts. 
 
Figure 25 — Current desktop Program Stage Flow 
Component behavior BI relevance 
Eight stages with Completed, Current, Selected, Pending Approval, 
Returned and Upcoming states; each stage carries progress and 
accessible state labels. 
Use the same eight-stage conformed dimension in Power BI. Do 
not collapse the lifecycle to generic phases. 
Desktop/laptop/tablet landscape uses horizontal stepper; <=820 px 
uses vertical timeline. 
BI reports should use the same stage order for stage distribution, 
aging and bottleneck visuals. 
Overall readiness summarizes current Program stage progress; stage 
click inspects details without changing actual current stage. 
Separate current stage, selected/reporting context, and historical 
stage events in the analytical model.

Stage Governance summary 
5. Readiness, Delivery & Assessment Readiness, session delivery, incidents, assessment and certification evidence are completed; 
Academy Manager finalizes Stage 5. 
6. Graduate Outcomes Eligible graduates/outcomes evidence or N/A basis is recorded; Academy Manager finalizes

7. Reporting & Improvement Performance report, feedback and improvement actions are completed; Academy Manager 
opens Final Closure. 
8. Final Closure Academy Manager alone performs final Program closure. 
 
Stage Completion UX & Audit Requirements 
• Each stage must expose requirements, progress, missing items, blockers, ownership, readiness, completion action and 
next-stage information. 
• When completion is unavailable, exact blockers are shown rather than relying on a disabled button alone. 
• On successful completion the status, lifecycle, audit trail and next-stage work update immediately, with duplicate actions 
prevented. 
• The Manager Control is visible only to the Academy Manager; contributors may complete their own deliverables but 
cannot perform the final lifecycle handoff. 
Commercial Stage - B2C / B2B / Mixed 
Section 4B contains explicit Commercial Completion Readiness. B2C, B2B and Mixed routes validate their relevant 
requirements and expose exact blockers. Valid completion activates the next operational work idempotently, so repeated 
completion does not create duplicate assignments. 
BI opportunity 
Model Commercial Type as a conformed dimension and analyze route-level cycle time, readiness, revenue, conversion and 
completion performance.

The Python server persists operational state in SQLite while storing flexible JSON payloads in key entity tables. The 
package also supports JSON store compatibility and Excel import/export. This is appropriate for the prototype but should 
not be copied directly into the Power BI semantic model.
